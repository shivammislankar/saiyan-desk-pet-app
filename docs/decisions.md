# Decisions

This document records technical decisions and conflicts between the spec and actual platform behavior.

## D1: Project Location

**Decision:** Project lives at `D:\Projects\saiyan-desk-pet` per spec section 0.1.

**Rationale:** Avoids OneDrive sync issues with `node_modules`, avoids spaces in paths that break native-module builds, avoids Windows 260-character path limit.

## D2: Cache Locations

**Decision:** npm cache at `D:\dev-cache\npm`, Electron cache at `D:\dev-cache\electron`, electron-builder cache at `D:\dev-cache\electron-builder`.

**Rationale:** Keeps all dependency caches off C: drive per spec.

## D3: Development Data Directory

**Decision:** Dev scripts use `D:\Projects\saiyan-desk-pet-data` as the data directory, controlled by `GOKUPET_DATA_DIR` environment variable.

**Rationale:** Keeps private sprites and user data out of the repository.

## D4: Electron Version

**Decision:** Use the latest stable Electron version compatible with Node.js 24.x.

**Rationale:** Ensures compatibility with current Node.js LTS and native modules.

## D5: TypeScript Configuration

**Decision:** Strict mode enabled, `moduleResolution: "bundler"`, target ES2022.

**Rationale:** Strict type safety required by spec. Bundler resolution works well with Electron's module system.

## D6: Testing Framework

**Decision:** Vitest for unit and integration tests.

**Rationale:** Fast, TypeScript-native, good Electron mocking support.

## D7: Schema Validation

**Decision:** Zod for all untrusted JSON validation.

**Rationale:** Type-safe, composable, good error messages.

## D13: Original Placeholder Character; Third-Party Art Stays Local

**Decision:** The repository's default pack is generated by `scripts/generate-placeholder-sprites.ts` (`npm run generate-sprites`) into `assets/goku/placeholder/`, with `assets/goku/actions.json` and `assets/goku/pack.json`. It depicts an **original** martial artist (red headband, short brown hair, teal gi, cream trousers), deliberately not styled after any existing character. `assets/goku/sprites/` and `assets/goku/sheets/` are git-ignored: they hold third-party or personal art and are only used to build local packs (`scripts/build-sheets.js`, `scripts/build-hd-pack.py`) under the git-ignored `packs/`.

**Spec conflict:** §8 asks for placeholders with a specific well-known character's signature look. Reproducing that look is itself the copyright/trademark risk §3 exists to avoid, so the default art is a distinct original character and the specific look is left to user-supplied packs (§3.2).

## D14: Local Packs from `packs/`

**Decision:** On start-up, `PackService` copies each `packs/<id>/` (pack.json, actions.json, PNGs only; id `[A-Za-z0-9_-]`) into `<data>/packs/`. If settings still say `"spritePack": "default"`, the most recently built local pack is used; an explicit `spritePack` always wins. `electron-builder.yml` excludes `packs/`, `assets/goku/sprites/` and `assets/goku/sheets/`, so personal art never ends up in an installer.

## D15: Pack Rendering Mode and Display Scale

**Decision:** `pack.json` may set `"rendering": "pixelated" | "smooth"` and `"displayScale"`. Pixel-art packs are drawn nearest-neighbour at a whole number of physical pixels per art pixel; smooth packs (painted/high-res art) use high-quality filtering at `displayScale`. The canvas backing store follows `devicePixelRatio`, and the pet window is sized from the idle frame (`pet:set-size`, validated in main), keeping the feet in place.

**Rationale:** §7 (no subpixel blur) and §5.3 (never assume 1 CSS px = 1 physical px). Fixes blur at 125%/150% Windows scaling.

## D16: Keyboard Scan Codes

**Decision:** `input-normalizer.ts` maps libuiohook scan codes (Space 57, Enter 28, Backspace 14, letters 16–25/30–38/44–50, …), not browser key codes. Modifiers report only a coarse kind (`alt`/`ctrl`/`shift`/`meta`/`other`), needed for the Kamehameha trigger key.

**Rationale:** The previous browser-code table mis-categorised most keys (Space as a number, modifiers as strikes).

## D17: Kamehameha

**Decision:** `core/kamehameha-trigger.ts` is a pure state machine (§12.1): double-tap of the trigger key within `kamehamehaTiming`, firing on the second **release**; other keys or modifiers cancel; key-repeat ignored; missed key-ups recovered after 500 ms; `kamehamehaCooldown` applies. The renderer plays the charge frames with an on-canvas chant, then asks main (`pet:fire-beam`, geometry only) to show the pack's beam image in a temporary, click-through, non-focusable overlay window that is destroyed 150 ms after the fade. The beam image path comes from the active pack's `pack.json` and is validated in main (PNG inside the pack, no `..`, no symlinks). Dragging cancels the sequence; keyboard strikes are ignored during it. The pet fires toward the side of the screen with more room.

## D18: Sound Effects

**Decision:** All sounds are synthesised with Web Audio in `renderer/pet/sound-fx.ts` (no audio files, §3.1). Off by default (`sound: false`); toggled from the tray. Strike sounds are rate-limited (45 ms) and a limiter prevents clipping. Main sets `autoplay-policy=no-user-gesture-required` because the pet window never takes focus.

## D19: Dependency Upgrades and `npm audit`

**Decision:** Upgraded to Electron 44, electron-builder 26, Vitest 5 (+ Vite 8) and esbuild 0.28; Node 22.12+ required. `npmRebuild: false` because `uiohook-napi` ships N-API prebuilds (ABI-stable across Electron versions); `uiohook-napi` moved to `dependencies` so it is packaged. CI runs `npm audit --audit-level=high`: every advisory is still printed, but the build fails only on high/critical.

**Rationale:** Electron 33 carried high-severity advisories. The remaining moderate advisory (GHSA-hp3w-g68c-fv3c, `sprintf-js` ≤ 1.1.3 via electron-builder → @electron/get → global-agent → roarr) has no patched release and only affects build tooling, not the shipped app. Revisit when upstream updates.

## D20: Tray Icon

**Decision:** The tray icon is an original generated badge with 1× and 2× representations (`main/tray-icon.ts`). Left-click opens the same menu as right-click until the settings window exists.

**Rationale:** The previous embedded icon data was truncated, so Windows showed an invisible icon and the tray menu (Sound, Pause, Quit) was unreachable.

## D12: Drag Without Per-Pixel Pass-Through

**Decision:** The sprite window accepts mouse input (`setIgnoreMouseEvents(false)`) so dragging works. Drag starts only on hit-tested sprite pixels; the main process follows the cursor on a 16ms poll, estimates release velocity from 200ms of history, and runs throw inertia with work-area bounce. Position persists to `position.json` (normalized + display id) on settle and restores on launch.

**Rationale:** True per-pixel pass-through is not reliably available, so the spec §5.2 fallback applies: closest reliable behavior + documented limitation. Transparent regions of the 256px window currently capture clicks instead of forwarding them.

## D11: Loose Frames Packed to Sheets *(superseded by D13)*

**Decision:** User-supplied loose frames (`assets/goku/sprites/base_*.png`, uniform 64x64 RGBA) are packed by `scripts/pack-sprite-sheets.ts` (pngjs, dev-only) into one horizontal strip per action under `assets/goku/sheets/`, with `actions.json` regenerated. Renderer canvas sizing changed from hardcoded 32px to 64px frames (`CANVAS_PAD 80 x scale`), and frame timing now honors per-action `fps`. Only the `base_` set is wired; `ssj_/ssj2_/ssj3_` sets are staged untouched for Phase 2/6 palette work.

## D10: Default Pack Sprite Seeding *(superseded by D13)*

**Decision:** `PackService.createDefaultPack()` now also copies `assets/goku/sprites/placeholder.png` into `<data>/packs/default/sprites/`, and repairs old installs that have `pack.json`/`actions.json` but no PNG.

**Rationale:** The loader failed with `Failed to load sprite sheet: .../packs/default/sprites/placeholder.png` because only the JSON manifests were seeded — the PNG lived solely under the repo's `assets/` folder, which the renderer never reads.

## D9: Renderer Bundling

**Decision:** Renderer entries (`pet/renderer`, `overlay/overlay-renderer`, `settings/settings-ui`) are bundled to IIFE with esbuild (`scripts/bundle-renderer.js`). Main/preload stay CommonJS via `tsc`.

**Rationale:** `tsc` emits CommonJS (`exports`/`require`), which crashes when loaded via plain `<script>` tags (`Uncaught ReferenceError: exports is not defined`). Bundling produces browser-runnable files without adding a new dependency (esbuild ships transitively via vitest/vite).

## D8: Native Module Compatibility

**Decision:** `uiohook-napi` and `active-win` will be verified against the chosen Electron version before Phase 2/4 implementation.

**Rationale:** Native modules must work in packaged apps, not just dev mode.
